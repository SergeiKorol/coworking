# Дизайн: публичная занятость v2 (план, оверлей, упрощённый каталог)

**Дата:** 2026-11-13  
**Статус:** утверждён пользователем («ок», вариант A)  
**Родительский scope:** [2026-11-10-coworking-flask-design.md](./2026-11-10-coworking-flask-design.md)

## Цель

Сделать **единственной публичной точкой входа** страницу `/availability` с вёрсткой по макету: шапка с логотипом и контактами, полоса 7 дат, схема помещения с оверлеем статусов, под схемой — **карточки** (вариант A). Упростить каталог и отображение: **1 переговорка** и **7 столов** только на **день**; убрать месячные столы и почасовую сетку переговорки. Скрыть админку от посетителей (без ссылки в UI).

## Вне scope этой итерации

- Возврат полноценной главной страницы.
- Почасовая переговорка (может вернуться позже).
- Кликабельная SVG-карта.
- Смена URL админки / robots / noindex (только убрать ссылку).

## Маршруты

| Маршрут | Поведение |
|---------|-----------|
| `GET /` | **302** (или 301) на `url_for('public.availability')` без query → сегодня |
| `GET /availability` | Как ранее: `?date=`, окно 7 дней, redirect вне окна |
| `GET /admin/*` | Без изменений; **нет** ссылки в публичных шаблонах |

Шаблон `public/index.html` не используется в потоке (можно оставить файл или удалить в реализации — на усмотрение плана).

## Каталог (код, без UI)

### Типы мест

| id | title (публичка) | granularity |
|----|------------------|---------------|
| `meeting_room` | Переговорка | `daily` |
| `hot_desk` | Столы | `daily` |

Тип `dedicated_desk` / «Столы (месяц)» **удалить** из `PLACE_TYPES` и `UNITS`.

### Единицы

| unit_id | type | display_name |
|---------|------|----------------|
| `meeting-room` | meeting_room | Переговорка |
| `desk-1` … `desk-7` | hot_desk | Стол 1 … Стол 7 |

### Бронирование (админка)

- **Переговорка и столы:** только **daily** — дата начала, дата конца (включительно); в БД полуинтервал дней, как сейчас для daily.
- Почасовые и месячные поля формы **не показывать** (убрать или скрыть через отсутствие типов).
- Правила валидации: без hourly/monthly для удалённых типов; переговорка — те же daily-правила, что у стола.

### Существующие данные

Старые брони с `unit_id` вне нового каталога (`room-a`, `desk-month-1`, …) в SQL **не удаляем** автоматически; на публичке не отображаются (нет unit в каталоге). При реализации — опциональная заметка в README для ручной очистки.

## Публичная логика занятости

- Источник: брони `status == confirmed`, пересечение с выбранным календарным днём (`[day_start, day_end)`).
- Для **каждого** unit из каталога: `occupied: bool` на выбранный день.
- **Нет** почасовых строк для переговорки.
- **Нет** отдельного типа «месяц».

### Сервис

Заменить/расширить выход `build_day_availability` (или новая функция `build_day_unit_statuses`) для шаблона:

```text
UnitStatus: unit_id, display_name, type_id, occupied: bool
```

Порядок: `desk-1` … `desk-7`, затем `meeting-room`. Табличные `SlotRow` / почасовые `TypeDayView` для публички **не использовать** в v2 UI (код можно упростить или оставить неиспользуемым — предпочтение плана: упростить под v2).

## UI `/availability`

### Структура страницы (сверху вниз)

1. **Шапка (тёмная)**  
   - Слева: `static/images/logo.png`  
   - Центр: «Коворкинг»  
   - Справа: адрес + телефон (телефон — ссылка `tel:`)

2. **Подпись даты:** «Занятость на ДД.ММ.ГГГГ»

3. **Полоса 7 дат** — логика без изменений; визуал ближе к макету (карточки, активная с синей обводкой).

4. **Блок схемы (full width)**  
   - Изображение: `static/images/floor-plan.png` (экспорт из приложенного макета, без шапки/дат).  
   - Контейнер `position: relative`.  
   - **Оверлей (вариант css_overlay):** для каждого из 8 unit — метка с текстом имени и «свободен» / «занят»; классы `.overlay-free` / `.overlay-busy`.  
   - Позиции: `static/data/floor-overlay.json` или константа в `app/catalog/floor_overlay.py` — пары `unit_id` → `top/left` в % для адаптивности.

5. **Блок карточек (вариант A)**  
   - Сетка: 7 карточек столов (на sm — 2–3 колонки, на md+ — удобная сетка).  
   - Ниже или рядом: карточка **Переговорка**.  
   - Содержимое: имя + статус; цвет согласован с оверлеем.  
   - Служебный текст: звонок для брони; только confirmed на сайте.

### Шаблоны

- Ввести `templates/public/base_public.html` (или переименовать использование `base.html` только для admin): **без** навбара с «Админ» и без ссылки на главную.  
- `availability.html` extends `base_public.html`.  
- Admin-шаблоны по-прежнему могут использовать отдельный `base_admin.html` с минимальной навигацией (без публичной шапки v2).

## Скрытие админки

- URL `/admin/login` остаётся; доступ по закладке/документации для оператора.  
- Не добавлять упоминаний админки в публичный футер.

## Тестирование

- `GET /` → redirect на `/availability`.  
- `/availability` 200; в теле нет строки/ссылки «Админ».  
- `build_day_*`: confirmed заняло стол на день → `occupied=True`; pending — False.  
- Каталог: 7 столов + 1 переговорка, нет `dedicated_desk`.  
- Обновить/удалить тесты почасовой сетки для meeting_room.
