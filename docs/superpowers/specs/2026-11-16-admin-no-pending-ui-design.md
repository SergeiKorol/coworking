# Дизайн: убрать pending из админки (подход B)

**Дата:** 2026-11-16  
**Статус:** утверждён (вариант B + подход B)

## Цель

Администратор после звонка сразу фиксирует **подтверждённую** бронь; отмена через **cancelled**. Статус **pending** не выбирается в UI и не принимается с POST при сохранении из админки.

Enum `pending` в БД и логике публичной страницы **сохраняется** для возможной будущей онлайн-брони.

## Поведение

| Действие | Статус |
|----------|--------|
| Новая бронь (админ) | Всегда `confirmed`; поле статуса скрыто |
| Редактирование | Только `confirmed` \| `cancelled` |
| POST с `pending` | Отклонение (flash + без сохранения) |
| Публичка | Без изменений: только `confirmed` занимает место |

## Старые записи

Брони с `pending` в списке видны; при редактировании админ выбирает подтвердить или отменить.

## Модель

`Booking.status` default → `CONFIRMED` (новые строки).

## Тесты

- Создание POST `/admin/bookings/new` → `confirmed`
- Edit choices не содержат pending; переход confirmed ↔ cancelled
